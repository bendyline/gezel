# 1.26300 — 27 October 2026

Thirteen days after **1.26287**. Your **gezellen** are the named AI craftspeople on your crew (one is a *gezel*). They can now watch a room through a webcam and act on what they see, following rules you write as a sentence. A project that holds a folder gets a **Views** tab that shows what is in it: on shelves, on a timeline, as a diagram. And AI apps you already use, such as Claude Code and Codex, can now use Gezel's search, document reading and memory while they work.

Smaller changes show up everywhere. The crew's titles are now in plain English, each request you send gets one card that runs from "Got it" to "Ready", and Home appears as soon as you open the app.

If you read only one thing: open a project that holds a folder and choose its **Views** tab.

## Keep an eye on a room

A project can now watch a room through a webcam or the camera built into your computer. Gezel notices when something moves and can ask a vision model on this computer what it sees. It saves each thing that happens as a **moment**: a short note with up to three pictures, so you can ask later, "when was the cat last in the mud room?"

A **lookout** says what to do about it, as a sentence you finish: *when the mud room camera sees a cat squatting on the floor, then play the alarm and tell me.* A lookout can tell you, play a sound, say something out loud, alert your phone, email you, ask a gezel to follow up, or run a craftbook. A craftbook is one of gezel's step-by-step recipes for a job. Each lookout acts at most once per moment, rests afterwards, and stops for the day at its limit. **Test** shows exactly what it would do, and **Not this** marks a false alarm.

The pictures stay on this computer. While any camera is watching, the titlebar says **Camera on**, and one click pauses it. A gezel on a cloud model gets a description made on this computer, not the pictures, unless you allow cloud models for that camera. A gezel can suggest a lookout, but the lookout stays off until you approve it. To add a camera, open a project's **About → Connections → Add connection** and choose **Webcam**. Gezel reads cameras through ffmpeg, and the setup shows how to install it if it is missing. More in [Cameras and lookouts](../conceptual/cameras-and-lookouts.md).

## Views: see what is in a folder

Once gezel has read a folder you added, the project's new **Views** tab shows what it found. The Village, the map that draws a codebase as a town, now sits there beside five new views:

- **Gallery** puts the files on shelves by type or by folder, and a photo folder by outing. A photo folder starts with its exact copies and look-alikes.
- **Timeline** shows what changed when, as bars by week, month or year. For a code folder the bars count commits. A photo sits at the time it was taken.
- **Diagram** draws files as boxes, with arrows to the files they use.
- **Guide** says what each folder of a codebase is for and which files the rest of it depends on.
- **Reports** gathers everything gezel has written about the project: overnight reports, code reviews, the codebase map. **Write … now** writes one straight away, so you don't have to wait for the night.

Choose a file in any view and a panel on the right shows a preview and says what the file is, what uses it, and any problems the Librarian (the crew member who reads your files) found. The file stays chosen when you switch views. Drawing a view never opens or changes your files, because every view comes from gezel's index of the folder. More in [Views](../conceptual/project-views.md).

## Gezel's tools in Claude Code, Codex and other AI apps

Until now, other apps could use your gezels and your models. This release also works the other way round. **Claude Code**, **Claude Desktop**, **Codex**, **Cursor** and **VS Code** can now use what Gezel knows and does. They can search the folder they work in (including the text inside Word, PDF, PowerPoint and Excel files), your document library, your memories and your knowledge catalogs. They can read Office files and images, make images and Word, PowerPoint, PDF or Excel files, and save a decision as a memory that Gezel and every other app will see.

Set up each app on its own tab in **Settings → Integrations**, which used to be called Connected Apps. Gezel adds one server called `gezel` to that app's settings and changes nothing else there. The tab also shows a line to paste near the top of the folder's *CLAUDE.md* or *AGENTS.md*. Without that line, apps tend to use their own search first. In our tests, the line made Claude Code on Sonnet 5 answer questions about code about a quarter faster, and up to twice as fast on large codebases with little documentation. Newer models that already find their way quickly were no faster.

You decide what these apps may do, under **Gezel's tools in other apps** on the Overview tab. Memory can be off, read-only, or saved to the project. Images can be limited to this computer (the default) or use any image engine you set up. A third setting decides whether apps may judge the night shift's issues. Apps never write to your own "About you" memories, and under Super Lockdown, the strictest security level, none of these tools are available.

**Checking the night shift's issues.** Overnight, a small model on this computer reads your code and flags what looks wrong. Many of those flags are not real bugs, and a stronger model can tell which ones are. In Claude Code, `/mcp__gezel__triage_issues` reads the code at each issue and records a verdict: fixed, real, not a bug, true but not worth fixing. `/mcp__gezel__fix_issues` also fixes the real ones. Each issue then shows the verdict and which app gave it. An issue judged not a bug no longer comes back the next night in different words. Kinds of issue that are almost never worth fixing are marked low confidence and left out of the counts and the morning review. An app without Gezel's tools can do the same through **Reports → Issues for review** and **Import answers**. More in [Integrations](../conceptual/connected-apps.md).

## Plain names, and one card per request

The crew's titles are now in plain English. The **voorman** is now the **Crew Lead**, the **Boekwachter** the **Librarian**, the **Klerk** the **Scribe**, and the **Keurmeester** the **Inspector**. Roles from the catalog follow suit: a Reisleider is now a Trip Planner. Only the **Meester**, the guildmaster who greets you and builds your crew, keeps a Dutch title. Existing gezels are renamed for you, and what they can do does not change. See [Your crew](../conceptual/the-crew.md).

When you ask for something that takes real work, the conversation now shows one card for it. Before, it showed a trail of task cards, crew introductions and receipts. The card moves through four stops: **Got it**, **Making it**, **Checking it** and **Ready**. It has one plain line in the voice of the gezel leading the work ("Dejan is drafting the invoices") and an estimate based on how long similar work took on this computer. At Ready, it holds the finished file. **Who's helping?** shows the crew working on it. When a review sends work back, the card never moves backwards.

## A sparkle key for your message

The message box now has a sparkle key beside Task and Send. It can **Make it clearer**, **Shorten** or **Fix spelling and grammar** in the message you are writing. **Review my message** suggests changes without making them. The result appears in the message box for you to read and edit, and nothing is sent until you press Send. **Undo** puts your words back.

## Asking for a picture

The image gezel, which makes pictures directly from your message, now has a strip above its message box. In it you choose the shape, the size (**Draft** for a quick look, **Standard**, or **High**) and the image model. You can also say the shape in your message. "A lighthouse at dusk as a phone wallpaper" now makes a tall picture of a lighthouse, not a lighthouse next to a phone, and the strip shows what it understood before you send. For image models that read whole sentences, the sparkle key adds **Shape for** that model, which rewrites your idea in the way that model understands best.

The catalog adds two image helpers. **MOSS-Image** is an on-device image model that writes clear, correctly spelled text inside pictures, such as signs, posters and labeled diagrams. The **Illustrator** is a gezel who turns a brief into a finished set of images, such as logos, icons or character sheets. They check the results and draw vector shapes by hand when the job calls for it. Image work in tasks and craftbooks now goes to the Illustrator.

## Connect another computer with a code

In **Settings → Remote Servers**, gezel can use the models on another of your computers, such as a desktop with a large graphics card, from your laptop. Pairing used to mean typing an address and then approving it on the other computer. Now it works like a network lobby in a game. Computers running gezel on your network appear in a list without any setup, and you connect by typing the 8-digit code the other computer shows under **Add a device**. **Connect by IP address** is still there for networks that hide devices from each other.

When a paired computer goes to sleep or you leave its network, your gezels carry on with this computer's own model, and the reply says so. Once the other computer can be reached again, the next message goes back to it. Its models stay in the model list, marked **(offline)**. The phone app can pair with a computer the same way, under **Another device**, and use its models.

## Windows on ARM

Gezel now has a Windows installer for computers with ARM processors. On a laptop with NVIDIA's RTX Spark (N1X) chip, on-device models run on its graphics processor. In our first test, a large 27-billion-parameter model read a prompt about thirty times faster than on the main processor alone, and wrote about fourteen times faster. Other ARM laptops run on-device models on the main processor for now. Searching your documents and memories works on all of them.

## Opening gezel

Home now appears as soon as you open the app, before gezel's background service has finished starting. It shows the Meester, their latest status and your recent night shift reports, ready to read. When the service is ready, the full app takes over and leaves you where you were reading. Starting up is also quicker, because gezel no longer re-checks every bundled program byte by byte at each launch. It checks a file again only when the file has changed.

On a new install, the photo-search model and the image reader now wait to download until your first project is finished, so your first few minutes aren't spent waiting for downloads. When the Meester starts a ready-made kind of project, such as a job-hunt board, the Crew Lead now has to fill in a first draft before calling the work done. An empty board no longer counts as finished.

## New in the catalog

- **New sources for a project**, under **About → Connections**. **Outlook Calendar** keeps a searchable copy of your calendars. **OneDrive**, **SharePoint** and **Google Drive** keep a searchable, read-only copy of the folders you choose. **RSS and Atom feeds** follow blogs, news sites and podcasts without any sign-in. **YouTube** keeps a copy of the videos on channels you run or follow, with a free API key. To connect Microsoft or Google, you first register an app with them yourself, and the setup walks you through it.
- **Chat models.** Liquid AI's LFM2.5 24B-A2B. NVIDIA's Nemotron 3.5 Bolt, in a 6 GB version and a 74B version that fits in about 24 GB, and Nemotron 3.5 Super VL 120B. A 2-bit DeepSeek V4.1 Flash for machines with a very large amount of memory.
- **Project types.** **Data Analysis** opens a folder's spreadsheets and data files in a live dashboard. **Media Library** lets you browse a folder of images, video and audio and play them where they are, without moving the originals.
- **Knowledge catalogs.** Wikipedia: History, Wikipedia: Geography & Places, and nine catalogs of notable people, including scientists, writers and artists, entertainers, sportspeople and politicians. Western Europe is now split into East and West.
- **Model scorecard.** Three new rounds: local models on an Apple M5 Max, eight small models on a Windows laptop with an RTX 5070 Ti, and NVIDIA's Nemotron 3.5 Bolt against four Gemma and Qwen models. Each round now includes a review of what every model actually made, not only whether it passed. See the [model scorecard](../technical/model-scorecard.md).

## Smaller things

- **Documents work right after you install.** DocBlocks, the document maker behind gezel's Word, PowerPoint, PDF and Excel files, now comes inside gezel. Craftbooks that make documents work on a fresh install and without an internet connection.
- **Search finds other forms of a word.** Searching for "transitions" finds documents that say "transition", and "rendered" finds "render".
- **Knowledge catalogs** list their articles in one continuous list with an A to Z index beside it, and keep your place when you come back.
- **Narration pronounces words the way they are meant.** The on-device voice pronounces "present" differently in "we present" and "at present", reads capitalized acronyms properly, and now uses a higher-precision copy of its voice model.
- **The Meester takes on work more reliably.** It now chooses from one ranked list of what suits a request (a craftbook, a kind of project, or a plain task), which on-device models get right more often.
- **Projects survive a crash.** If a crash or power cut empties a project's settings file, gezel rebuilds it from the project's history instead of dropping the project from your list.
- **Interrupted downloads repair themselves.** If a model file was cut short during a download, gezel notices and downloads it again, instead of failing every time it loads the model. A model that downloads in several pieces at once shows one steady progress bar.
- **Upgrades reach the background service.** On a Mac or Linux computer where gezel starts at login, an upgrade could leave the old background service running. Gezel now restarts it through the operating system until the new version is running.
- **Plain warnings about your graphics card.** Sometimes an on-device engine can't use your graphics card. On Linux, the NVIDIA driver may need a restart or an update, or a build may have started without its graphics card. On Windows, the Visual C++ runtime may be missing. The sidebar now says so in one line, such as "Restart to use your GPU" or "Install a Windows component", instead of running slowly without telling you. If an engine build crashes three times in a row before it is ready, gezel switches it off and uses the next build. You can turn it back on from the engine's page in Settings.
- **Built-in AMD graphics.** On AMD processors with built-in graphics, gezel now counts the memory set aside for graphics correctly, so it no longer misjudges which models fit.
- **NVIDIA on Windows.** The Windows graphics build now includes code made for RTX 50-series cards. GTX 10-series cards still work but need driver version R570 or newer.
- **Less disk space for Codex.** Chats that use the Codex provider no longer leave a folder of 5–9 MB behind forever. Folders that haven't been used for 14 days are removed.
- **Debug mode** switches on and off in open conversations straight away, without reloading.
- **The project picker in Chat** now sits in the tab row, beside Chat.
- **Poppetjes**, the carved figures that represent each gezel, now have lighting and shading that look more like carved wood.

## Security

None of these changes need anything from you.

- Pairing with another computer goes through a one-time code that ties together the identities of both computers. If a paired computer moves to a new network address, it has to prove it is the same computer before gezel connects to it there.
- Git and GitHub sign-ins are sent only to the site they belong to, and never appear on a command line where other programs could read them. Gezel asks the GitHub command-line tool for your sign-in only for projects linked to GitHub.
- Gezel treats what a camera's vision model writes as untrusted. A sign held up to the camera can't send an email or start work, because lookouts act only on yes-or-no answers and on your own instructions.
- The Windows installer repairs the permissions on gezel's service folder in a way that a folder link cannot redirect. If it can't finish the repair, it stops instead of leaving the permissions partly fixed. Upgrades are quicker when the folder hasn't been changed.

## In the terminal

- `gezel stop` now shuts the service down. `gezel stop --keep-running` is the emergency brake: it stops AI work but leaves the service running.
- `gezel craftbook list [words]` lists the craftbooks you can start in the current folder's project.
- `gezel mcp status`, `gezel mcp install <app>` and `gezel mcp remove <app>` manage Gezel's tools in other apps.
- `gezel do --wait` says why a task is blocked and points to `gezel task notes <ref>`.
- `gezel run --gezel` accepts a gezel's name or role.
- Install with `npm install -g @bendyline/gezel-cli`, or try it without installing with `npx -p @bendyline/gezel-cli gezel`. A bare `npx gezel` fetches an unrelated package.
- The terminal tool, the app SDK and the VS Code extension now check whether a running Gezel service speaks their version of the API. If it doesn't, they say which one to update.

See the [CLI reference](../technical/cli-reference.md).

## For developers

- **Pages.** Project-type pages can query a project's tables, open data files with `gezel.data.open()`, accept scoped uploads declared in `pages.imports`, and reuse the shared `fileCard` and `fileAdder` components. They inherit the host's fonts. `gezel app demo <folder>` exports an offline demo of a private app. New guides: [Page APIs](../technical/gezel-page-apis.md) and the [page style guide](../technical/gezel-app-page-style-guide.md).
- **App SDK.** A new `images` grant and `/v1/images/*` routes with streamed progress. An app can add scopes to its grant without disconnecting. `knowledgeContext()` reports whether knowledge was used and returns the passages, and accepts an explicit `query` and numbered citations. In-process hosting takes `logOutput`, and embedded daemon logs go to stderr by default.
- **Grounding.** The citation checker that gezel runs for factual writing is published as `@bendyline/gezel/grounding`.
- **OpenAI-compatible routes** return typed error codes when an engine fails (capacity, busy, launch failure, crash, context overflow, not ready). Downloadable `/v1/models` entries say how well each model fits the device.
- **Remote serving.** The `/v1/remote/*` wire contract and SPAKE2 pairing live in `@bendyline/gezel/remote`. New routes: `/api/remotes/pair-with-code`, `/api/remotes/discover` and `/v1/apps/pair/start|finish`.
- **API compatibility.** `/api/health` publishes an `apiCompat` range. Clients decline a daemon outside that range with `daemon_incompatible`.
- **Native engines** are pinned to release 0.1.54, which adds CUDA builds for Windows on ARM.

## Things to see and do after update

Open a project that holds a folder and choose **Views**. Try the Gallery on your Pictures folder, or the Guide on a codebase. If you use Claude Code or Codex, set up **Gezel's tools** for it in **Settings → Integrations**, and paste the line it shows into that folder's instructions file. If you have a second computer running gezel, pair the two in **Settings → Remote Servers**. And if there is a room you would like watched, add a **Webcam** under a project's **About → Connections**.
