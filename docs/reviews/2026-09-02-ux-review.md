# State of Gezel UX — September 2, 2026

A screenshot-grounded review of the first-run experience and the day-to-day
"warm" workshop, measured against the app's own promise: warm, named
companions that make AI accessible to everyone. Produced on branch
`bendymike-iterationimprovements9.1` (Windows 11, 1440×900, light and dark).

**Method.** Two new permanent Playwright specs drive the built Electron app
end-to-end and double as UX regression coverage:
[ux-first-run.spec.ts](../../packages/app/e2e/ux-first-run.spec.ts) boots a
genuinely fresh home (no mock provider, the real llama-cpp pin, the download
CTA never clicked) and [ux-tour.spec.ts](../../packages/app/e2e/ux-tour.spec.ts)
builds a warm world through the UI itself — a chat turn with the Meester, a
created gezel, a Language Trainer project from the gallery — then walks every
area, all seventeen Settings sections, search, and dark mode. 43 screenshots
land in `packages/app/screenshots/ux-tour/` (gitignored, wiped once per run
via Playwright globalSetup). Every screen referenced below was read at full
resolution; flow-level claims were verified in the UI code.

A designed HTML version of this report, with the evidence screenshots
embedded, was published as the "State of Gezel UX" artifact.

## Verdict

The warm-workshop identity is real and it lands — the Home greeting with the
Meester's poppetje, the personalized composer placeholders, the two-step
galleries, and the Handboek are genuinely distinctive and better-crafted than
most AI products. The gap is no longer aesthetic; it is a **seam between the
story and the machinery**. The first thing a new user must do (download one
model) is visually out-shouted by five optional downloads; the first task they
will ever see is an internal indexing job written in engineering dialect; and
the character pages that carry the "crew" promise open with
`Context: Lean/Balanced/Deep` keys and raw ids like `gezel-1`. Gezel's biggest
UX wins from here come from hiding its own plumbing, not from new surfaces.

## What already works

- **The Home workshop is a great first screen once configured.** "Good
  morning." in serif, a tip of the day, the Meester's poppetje with name and
  role, three answer chips that teach what to ask, and a composer that talks
  like a person ("Got a half-baked idea? Rosalind will help shape it into
  something your gezels can actually start on."). `warm/01`
- **Composer placeholders are personalized per gezel and rotate.** "No wrong
  questions. Bauyrzhan has probably heard weirder." The crew promise,
  delivered in microcopy. `warm/10`
- **The two-step galleries are the app's best pattern.** New Project and New
  Task both: subject-shelved rail, workshop-mark artwork, a reassuring footer
  ("nothing is created until the next screen"), a configure step that
  auto-suggests a name. `warm/08–09, warm/12`
- **Security & Compliance is written for humans.** "Slide toward lockdown to
  make Gezel safe to try; loosen it as you build trust." Every capability
  switch explains its consequence honestly. `warm/21-settings-security-compliance`
- **The seeded "About this library" document** teaches the shared library by
  being a document in it — including "You can delete this document once the
  library has content of its own; nothing re-creates it." `warm/13`
- **History reads as a story** ("Generated initial poppetje for Tessa —
  Portrait carved", "Rosalind joined 'Default'"), master-detail, honest audit
  fields. `warm/16`
- **The Handboek** is a proper manual: concepts, roles, craftbooks,
  Document/Video toggle, clean serif typography. `warm/18`
- **Dark mode's workshop dusk** (`#1f1c18`) keeps the warmth instead of going
  corporate black — on the Home surface. `warm/40`
- **Accessibility bones are good.** The aria tree during testing showed real
  roles and labels throughout — radiogroups for keys, named buttons, labeled
  regions.

## Part one — first run: the story is missing from the first five minutes

The onboarding screen works mechanically — one click, one model, honest time
estimates. But it reads as a settings form, and its visual hierarchy actively
fights the one thing the user must do. Evidence: `first-run/01`.

1. **Critical — the visual hierarchy is inverted.** The single required step
   ("Download recommended model (Gemma 4 (E4B), ~3.9 GB)") is a pale,
   low-contrast button inside a quiet banner. Directly below it, the
   *optional* media section gets the bold terracotta "Choose downloads ·
   ~5.6 GB" plus five terracotta-outlined download rows, one of them a
   31.9 GB video model. The eye goes to the optional stack; the one click
   that unlocks chat is the quietest thing on the page.
2. **Critical — there is no character on the first screen.** The soul of
   gezel is "warm, named characters, not chat sessions" — but the first five
   minutes contain no poppetje, no Meester, no crew. The heading is "First
   run setup", the lede name-drops Hugging Face, the buttons list model SKUs
   ("FLUX.2 Klein 4B (Q4)", "Wan 2.2 TI2V-5B"). Meanwhile Rosalind, Lukas,
   and Tamara already exist in the sidebar, unintroduced. Even one warm
   element — the Meester's poppetje "waiting for the workshop to open," a
   line in their voice — would carry the story across the download wait.
3. **Major — the decisions below the fold matter more than what's above it.**
   The Security & Compliance posture — the one choice with real consequences —
   sits below "Experience / Boring mode", below five optional downloads, cut
   off at the fold at 1440×900. "Boring mode" is a fun toggle for later, not
   the second decision of a first run, and it leads with an in-joke label
   before the user has met a single named gezel.
4. **Major — jargon contradicts the mission on the screen where it matters
   most.** "Download local models from Hugging Face" / "Q4" / "TI2V-5B". The
   device-fit copy ("You can run large AI models comfortably on this device")
   is the right register; the rest of the page should match it, with SKUs
   demoted to detail text.
5. **Minor — what already works here:** the sidebar's "Get started" relabel,
   the "Manage Chat AI Models →" escape hatch, and (verified in code) the
   exemplary failed-download banner: retry, checksum-mismatch "download
   anyway", provider escape hatches, error-report link, each explained.

Also noted while building the harness: HomeView holds the loading splash until
the provider probe settles, with a 30-second anti-strand fallback. On a
genuinely fresh machine the llama-cpp probe fails fast (it is a model listing)
so onboarding appears quickly; the long-splash path only bit under this
machine's contaminated model overlay (see Part three).

## Part two — day to day: the machinery keeps walking into the workshop

### The plumbing leaks

1. **Critical — the Tasks area leads with a system job on day one.** A fresh
   install's task list contains "Boekwachter: workspace indexing &
   enrichment" (`default/2`, "Tamara · system-run"), described in engineering
   dialect ("symbols and search while idle, AI summaries, folder rollups,
   weekly digests in bulk during Night Shift… the cheap structural scan keeps
   search working"). Visible and pausable is the right instinct — but as the
   first and only row it teaches "tasks are system things I don't
   understand," exactly when the app wants to teach "tasks are work I hand my
   crew." A collapsed System shelf would keep the honesty without the noise.
   `warm/11`
2. **Major — character pages open with engine controls.** Every gezel detail
   header carries `Model:`, `Context: Inherit/Off/Lean/Balanced/Deep`,
   `Sandbox: Inherit/On/Off` — unlabeled trays with no hint text, above the
   character's own tabs. Real power-user controls, wrong altitude: move them
   behind an "Engine" disclosure or tab and give the header back to the
   character. `warm/06`
3. **Major — raw ids stand in for missing roles.** A gezel created without a
   role shows `gezel-1` as their sidebar subtitle, while the Gezellen rail
   shows a blank line for the same gezel. Fall back to something human,
   consistently. `warm/06`
4. **Major — the gender guess survives a rename.** The New Gezel dialog
   pre-fills a random name and guesses a gender for it ("Arjun" →
   "male (he/him)"). Rename to "Tessa" and the guess stays: her page reads
   "Talk to Tessa about what *he* is working on." Re-derive the default on
   name edits, or start neutral. `warm/05–06`
5. **Major — Craftbooks lands in the authoring editor, not the library.**
   The area drops the user into the read-only editor of the first
   alphabetical book — step forms, "Context token cap", raw model prompt text
   ("Use write_task_note for the brief…"). New Task proves the same catalog
   presents beautifully as a gallery; browsing should be the landing.
   `warm/14`
6. **Minor — assorted machine syntax in human places.** `inherit · Tamara`
   unlabeled on the task step header; History surfacing "Indexed context
   retrieval found nothing above t…" as a top-level event; a release-notes
   article titled "1.26244 — 1 September 2026" in search results; the project
   chat pane's `Do +` button. `warm/11, 16, 20, 10`

### Pattern debts against docs/ux.md itself

7. **Major — loading text where the placeholder pattern belongs.** The gezel
   surfaces show bare "Loading…", "Loading projects…", "Model: loading
   providers…" during hydration — ux.md's wordless-structural-stand-in rule
   is implemented for project switches but not here. `warm/05, 07`
8. **Major — search results don't say how they were found.** "tour" surfaces
   "Photo Cull & Rank", "Notification Router", "Quarterly Shoebox Summary"
   with no cue why. ux.md already mandates a `related` badge for
   non-keyword document hits; the titlebar palette needs the same honesty or
   tighter fuzzy matching. `warm/20`
9. **Minor — heavy editors for light jobs.** A task's Description and Notes
   each mount a full squisq toolbar (~20 controls) plus a word-count status
   bar — two stacked toolbars for what is usually two sentences. `warm/11`
10. **Minor — small frictions worth a sweep.** "Rosalind -" dangling hyphen
    under the greeting poppetje; the first thread auto-titled "Around" (title
    derivation picked a preposition out of "…around here?"); an Archive
    button on a zero-message thread; the Documents rail search box truncating
    to "Documents - searc" beside five icon-only keys; the crew list rendered
    twice on screen at once in the Gezellen area (area rail left + global
    sidebar right). `warm/01, 02, 13, 05`

### Dark mode: two palettes, one seam

11. **Major — the titlebar never goes dark.** In explicit dark mode the
    content flips to dusk but the titlebar keeps full daylight sage with the
    cream search pill — a hard seam across the top of every dark screen,
    harshest on first-run where the body goes near-black beneath it. If the
    sage band is a brand constant, it needs a dusk variant of the same
    wood-grain. `warm/40, 42, first-run/04`
12. **Minor — dusk warmth is inconsistent.** Home's dark ground is the warm
    `#1f1c18` the design doc specifies; the sidebar and first-run body drop
    to a colder near-black. Align on the workshop's dusk tokens.

### Defaults worth a deliberate look

13. **Minor — sidebar defaults to the right; AI engagement defaults to
    Proactive.** Both legitimate, both unusual enough to deserve recorded
    rationale: right-hand navigation surprises desktop users (Settings offers
    Left), and Proactive-by-default spends tokens on check-ins before the
    user has a model of what the crew does on its own. The "panic button"
    framing in Settings → Your Team is good; the question is whether day one
    should start a notch lower.

## Part three — coverage: what the tour now guards

Both specs are permanent members of the Electron suite (`pnpm test:e2e`) and
assert each surface's signature element, so a broken area now fails CI — and
every run rebuilds the full screenshot set for visual review.

| Spec | Covers | Screenshots |
|---|---|---|
| `ux-first-run.spec.ts` | Real unconfigured llama-cpp boot; download CTA present and never auto-fired; "Get started" label; intro on the setup page; dark mode | 4 → `screenshots/ux-tour/first-run/` |
| `ux-tour.spec.ts` | Home workshop + live chat round-trip; tour tab; sidebar groups; gezel create dialog → detail; Gezellen area; New Project gallery both steps → created Language Trainer project with live dashboard; Tasks + New Task gallery; Documents, Craftbooks, Scripts, History, Knowledge, Handboek; titlebar search palette; all 17 Settings sections by label; dark variants | 39 → `screenshots/ux-tour/warm/` |

Three harness fixes rode along, all of which bit during this review:

- The screenshot wipe moved to Playwright `globalSetup`
  ([clean-ux-tour-shots.ts](../../packages/app/e2e/helpers/clean-ux-tour-shots.ts)) —
  a beforeAll wipe re-runs on failure-triggered worker restarts and deletes
  the evidence already captured.
- [buildLaunchEnv](../../packages/app/e2e/helpers/launch-env.ts) now scrubs
  `GEZEL_SHARED_ASSETS_DIR`: the machine's ProgramData model overlay was
  leaking multi-gigabyte llama.cpp installs into every "fresh" test home, so
  a first-run spec was never first-run locally while CI stayed green — the
  same class of rot as the machine-shared-home scrub above it.
- Benchmarks is deliberately untoured: TabContent routes it to Settings
  without `debugMode` — a developer surface, not shipped UX.

## Part four — what to fix first

| Priority | Change | Why it moves the needle |
|---|---|---|
| P1 | Re-weight first-run: required model download gets the primary treatment; optional media becomes one quiet "add later" row; plain-language names with SKUs demoted | The highest-leverage screen in the product; today its hierarchy points users at the wrong 5.6–31.9 GB |
| P1 | Put the Meester on the first-run screen — poppetje, name, one line in character; introduce the day-one crew | The core differentiator is invisible for the entire first session |
| P1 | Shelve system jobs out of the default task list (collapsed System group) and translate their descriptions | First contact with Tasks currently teaches "tasks are internal machinery" |
| P2 | Dark-mode pass: dusk titlebar variant, one warm dark temperature across sidebar/first-run/settings | Dark currently looks half-flipped on every screen |
| P2 | Move gezel engine controls behind a disclosure; kill `gezel-1`-style id fallbacks; re-derive the gender default on rename | Character pages should lead with character |
| P2 | Craftbooks area lands on a browse gallery; editor behind "Copy to edit" | The reading surface exists (New Task proves it); the area points at the wrong one |
| P2 | Apply the placeholder pattern to gezel surfaces; badge or tighten non-keyword search hits | Both are existing ux.md rules — enforcement, not design |
| P3 | Microcopy sweep: "Rosalind -" hyphen, thread-title derivation, `Do +`, `inherit · Tamara`, empty-thread Archive, truncated Documents search box | Cheap fixes, each a small restoration of the "well-made tool" feel |
| P3 | Record (or revisit) the right-hand sidebar and Proactive-engagement defaults | Deliberate-looking defaults deserve written rationale; surprising ones deserve a second look |
