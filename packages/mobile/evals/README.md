# Native product evaluations

`pnpm mobile:eval` runs the packaged shared app inside its actual Android WebView or iOS WKWebView. Only the instrumentation/XCTest bundle contains this harness. The release app has no evaluation endpoint, model override, or test global.

Build and sync the current mobile app before running. Use a dedicated emulator or simulator: the tests preserve its existing product tree and model selection, create a fresh product tree for every quality trial, and restore the original at teardown. Each phase reloads and verifies its files and sessions before the next tree is created. The native model inventory stays available across trials. Do not kill the native test process while it is restoring files. If forced termination leaves an unresolved `product-eval-backup-*`, the next eval refuses to replace or reinterpret it; recover the original tree explicitly first. A failed run retains its native report and partial evidence. The native wrapper hashes its packaged `public/index.html` and the exact injected test source. The launcher compares both with the current web build and harness before grading, rejecting stale copies; Vite's hashed module and stylesheet references in the index identify the production bundle.

```sh
# CPU-only product contracts: no model inference or device-eval lock.
pnpm mobile:eval --platform ios --device <simulator-uuid> --contracts-only --out /tmp/gezel-ios-contracts
pnpm mobile:eval --platform android --device emulator-5554 --contracts-only --out /tmp/gezel-android-contracts

# Real model quality: no artificial provider responses.
pnpm mobile:eval --platform ios --device <simulator-uuid> --provider apple-foundation-models --out /tmp/gezel-ios-quality
pnpm mobile:eval --platform android --device emulator-5554 --provider llama-cpp --trained-model /absolute/path/trained.gguf --out /tmp/gezel-android-quality

# Compile test code without running it; reuse caches to conserve disk.
pnpm mobile:eval --platform ios --device <simulator-uuid> --build-only

# Regrade retained native evidence with the unchanged canonical graders.
pnpm mobile:eval --platform ios --report-only /tmp/gezel-ios-quality/native-report.json --out /tmp/gezel-ios-regraded

# Record exact production prompts and host admission without a model or tokenizer.
node scripts/run-with-dependency-lease.mjs --direct-node evals/src/mobile/prompt-budget.ts /tmp/gezel-mobile-prompt-budget.json
```

Quality runs acquire the same exclusive device lock as desktop evals. An occupied lock stops the launcher; it never interrupts another run or silently runs concurrently. The launcher installs the app/test builds, but performs no model downloads or dependency installations. Android uses `adb install -r` and direct instrumentation, leaving the app installed; it never delegates cleanup to Gradle connected tests. Its report verifies the original product file digests and model inventory after teardown and is fetched from the still-installed app container. Android tests require the selected device to be the only connected device and to match `GEZEL_ANDROID_TEST_AVD` (default `gezel-api36-tests`). Android's `--trained-model` stages an existing GGUF into the test app cache, imports it through the real native model store, and removes that temporary cache copy immediately after import. The temporary imported model is removed at teardown. The launcher checks free space for both copies plus reserve, verifies the staged SHA-256 against the host file, and removes only its own staging path on failure or completion. Allow enough emulator memory for the model; the normal native size and resource limits still apply. iOS accepts `GEZEL_MOBILE_SPM_DIR` for an existing Swift package cache and `--native-build-dir` for derived data; simulator builds disable code signing.

The separate contract phase creates and edits a TypeScript script through normal product APIs, checks compiler errors, and runs QuickJS into a real artifact. Test-only interception at the native provider boundary supplies deterministic completions and readiness to exercise ordinary crew-message metadata, targeted file edits, generalist task continuity, and streamed text transforms. Unexpected completion requests fail closed, and the original boundary is restored before reload. These are product mechanics checks, not native inference or quality evidence. The app then reloads, opens the restored shared question card, and clicks **Skip**, verifying that skipping starts no model turn. Further reload checks preserve artifacts, script audits, message metadata, completed tasks, question answers, and chat transcripts.

Seven `mobile-product-v1` quality trials cover text artifacts, scoped file transformation and confinement, memory recall in a fresh session, audited bundled script transformation, crew handoff, rejecting/approving task gates, and interruption followed by another real response. Every trial has explicit assertions and retains its actual sessions, tool records, file contents, time budget, latency, and provider identity. Trial and outer quality deadlines use the unchanged shared `AwakeBudget` clock compiled into a test-only resource; reports separate awake duration, wall duration, and suspended time. Long suspensions retain the shared clock’s explicit abandonment behavior. Regenerate the clock resource with `node scripts/run-with-dependency-lease.mjs --direct-node evals/src/mobile/clock.ts` after shared clock changes; the launcher does this automatically. Context and output defaults match the product defaults and are capped by the provider's advertised limits. Optional `--context`, `--max-tokens`, and `--trial-timeout-ms` are recorded; the last flag affects workflow probes only.

Ten `canonical-core-native` trials reuse the desktop setup function itself to capture exact project briefs, role names, evidence files, prompts, and budgets: incident-postmortem, conflict-synthesis, data-wrangle, tictactoe, tankcombat, schema-migration, failing-tests-spec, symptom-debug, ops-runbook-anomaly, and plan-and-estimate. The host runs the unchanged success checks on bytes and tool provenance actually produced on the device. Game HTML is graded in host Chromium, away from the native bridge; source-edit scenarios use the original frozen host acceptance checks. Host tools grade output only and never perform the model's requested work. Missing grading tools fail honestly. The canonical source digest is pinned in packaged fixtures and verified again during grading. Regenerate fixtures with `node scripts/run-with-dependency-lease.mjs --direct-node evals/src/mobile/fixtures.ts` after a scenario change.

Canonical feedback crosses an app-private file mailbox owned by the test wrapper. The host preserves each scenario's original grading state, repair deduplication, terminal failures, and exact repair/nudge arguments. The app sends those receipts through ordinary product messaging routes to the retained recipient/session, waits for its real native turn, and supplies a fresh snapshot until the unchanged scenario gate or declared awake budget ends. A deterministic native-artifact SHA-256 round trip checks this mailbox separately. No production route or network listener is added. All eleven core scenarios appear in coverage: `petshop` remains unsupported because its fixed brief requires actual image generation. Unsupported or unrun cases never count as passes; ten adapters are not a complete core-eleven score.

`report.json` and `report.md` separate workflow, canonical, and contract outcomes. Each quality trial directory contains `trial.json`, `facts.json`, `result.json`, `score.json`, and safely named artifact copies. Scores use the repository's fixed rubric; qualitative prose/visual judgment and failure postmortems still require reviewing the saved evidence. Native unavailability, errors, and assertion failures return a failing exit code. `--scenarios` accepts a comma-separated subset for diagnosis without changing the prompts or success gates.

Quality trials reuse the desktop stateful auto-answer policy for ordinary product questions, including its original 30-second Meester inline idle threshold measured against native snapshot time, so host/device clock skew cannot shorten it. The host sends exact answer bodies over the test mailbox; the packaged app applies them through ordinary question/session APIs and records every successful intervention, its recipient, original question, answer, and elapsed awake time. Consent intents, model/download/install confirmations, privacy permissions, and native UI are never answered. Role creation and behavior red flags are derived from retained native rosters and transcripts using the shared desktop scoring rules. Missing behavior evidence prevents a passing result.

After each trial—including provider errors and budget exhaustion—the app snapshots the original workspace/artifact paths and exact UTF-8 or binary contents before product isolation is removed. Per-trial artifact files and `trial.json` preserve this partial evidence. Failed reads retain previous bytes with explicit capture errors; missing capture or reload evidence cannot count as a pass. The script-transform probe verifies the complete resulting repair record, including numeric `count: 3`, and requires successful script audits without direct file-edit substitutes.

The packaged mechanics phase also saves a task-scoped prompt draft before reload, reopens and duplicates it with its task reference intact, rejects reassignment/sending to an unrelated session, and sends the original through the ordinary session API. A separate reload verifies the sent original, unsent duplicate, and retained task transcript. These completions use the same fail-closed test-only provider interception as the other mechanics checks; they are not quality results.
